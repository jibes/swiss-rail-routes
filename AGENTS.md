# swiss-rail-routes: agent notes

Follows the portfolio standard: https://github.com/jibes/apps-data/blob/main/STANDARD.md
List deviations from it here, each with a reason. Product spec: [`docs/SPEC.md`](docs/SPEC.md). Design: [`docs/DESIGN.md`](docs/DESIGN.md) (principles, tokens, screenshot review).

Status: 0.64.1. One object, one screen, one line (SPEC §3a): every trip dated (new ones today, from now; going back up to two weeks, 0.49.0), planned while edited, edited whenever it is (0.52.0: its time decides only whether it is live), the same line under way and shared; answers kept on the device; past trips folded under the list. Android shell with trip notifications. MCP server in `mcp/`. SPEC §3 done (0.47.0), §9 questions answered (0.47.1).

## Stack

- TypeScript strict, React 19, Vite, vite-plugin-pwa, zustand, MapLibre GL, idb-keyval, fast-xml-parser, Vitest, Playwright. Node: see `.nvmrc`.
- One Cloudflare Worker in `workers/ojp/` holds the opentransportdata.swiss keys.
- Check library APIs against the installed types in `node_modules`, not from memory.
- Cloud sessions: Playwright uses `CHROMIUM_PATH` (set by the SessionStart hook); never run `playwright install` there.

## Architecture

- `src/core/` is pure logic with no DOM, and every module is covered by tests in `tests/` (most by a file of their own; `rows`, `pastTrips`, `refresh`, `connection`, `ics`, `share`, `b64`, `keys`, `export/tripLinkPacked` inside their neighbours': `line.test.ts`, `tripLink.test.ts`, `export.test.ts`).
- The planner (`src/core/planner/`) gets all I/O injected (`fetchTrips`, templates, GA rules, stops and places); tests replay `tests/fixtures/ojp/`.
- `src/core/ojp/request.ts` is shared with the Worker; the Worker builds requests only from typed JSON and never forwards client XML.
- `workers/ojp/src/handler.ts` uses only the standard Fetch API with injected deps (tested in Node); `index.ts` wires Cloudflare bindings.
- OJP facts found in recorded answers (Nov 2026), relied on by `src/core/ojp/parse.ts` and the planner:
  - Only the **first** `<Via>` of a TripRequest is enforced. The planner asks once with all vias and, when no answer passes them all, splits the leg at the vias and stitches the answers (`src/core/planner/stitch.ts`). A leg with many vias can be too much for one request (504 after 25 s, log of 6 Nov 2026: Zürich > St. Moritz, Gstaad, Montreux > Erstfeld): its failure is asked at its vias too (`plan.split`); a request stopped by an edit (`AbortError`) stops the plan.
  - A leg cannot end where it starts; round trips without a stop turn at the middle one of your own stations, never at a line's ring (`splitLoops`).
  - Category `PE` is also used for regular trains (Luzern-Interlaken Express). Reservation-only panorama trains carry attribute `A__PR`; product names (`BERNINA EXPRESS`) are matched against `ga.json`.
  - Cog railways come as PtMode `telecabin`/`funicular` with category `CC`; replacement buses as `EV`.
  - OJP passes the first via by its exact stop, walking through the station when the train or bus stops beside it (EV at "Bergün/Bravuogn, posta" → walk to Bergün/Bravuogn → back; boat to "Luzern Bahnhofquai" → walk to Luzern). So a via counts as passed when any section, walks included, reaches it (`visited` in `connection.ts`); the line folds walks under a minute, and a walk out and back to the same stop, into one row with both stops (`rows.ts`: Bergün is one row, arriving and leaving, not two 8-minute walks). Walks carry their minutes (`walkMin`, from `<Duration>`), and a connection's dep/arr include walks at its ends.
  - Cancelled trains and stops not served (`Cancelled`, `NotServicedStop`) are dropped from trip answers.
  - How full a train is expected to be comes with its calls (`ExpectedDepartureOccupancy`: `FareClass` and SIRI's `OccupancyLevel`; second class written `secondClass ` with a space, so both are trimmed), for SBB's and SOB's trains only in the recorded answers (none for the RhB or the Bernese Oberland's). `Section.occupancy` (0.39.0, `occupancyOf` in `parse.ts`) is the fullest per class from where you board to the last stop before you get off, in three steps (1 seats free, 2 few seats, 3 standing room or worse); the ride says it for the trip's class only from 2 on ("Few seats free", "Standing room only", `.occ`), and the MCP's rides as `occupancy: { first, second }` (`low`, `medium`, `high`). Not scored; links do not carry it (refresh asks again). e2e: `e2e/occupancy.spec.ts` (T2).
  - OJP marks no train running on (no stay-seated element in any recorded answer): the same journey keeps its `JourneyRef`; one renumbered at a stop is two rides. `runsOn` (`src/core/planner/connection.ts`): the same journey, or two rail rides at the same stop within a minute from the same track (sector letters left out: `2AB`, `2CD`) are one train: no change counted (`changesOf`), no tight transfer, no platform line, no depart/exit notice; the station says "The train continues as S1" (`continuesAs` in `src/core/changePlatform.ts`). Also a train renumbered on the way (0.43.0, reported: L3 to Coppet into Annemasse, RL3 to Coppet out of it 7 min later; in the recorded answers the RE7 split at Ilanz and the train to Filisur renumbered at Davos Platz): the same destination (`DestinationText`), the same line number but its letters, within `RENUMBER_MIN` (10), the same track where both are known, said as "The train probably continues as RL3" (`likely`). A `#/s/` link does not carry destinations, so until it is asked again such a train counts as a change. A change missed by at most `HOLD_MIN` (2 min) beyond its walk counts as made once the onward train has left (`liveState`, 0.42.0: "here" stayed at Vallorcine, a minute short, through a stay at Chamonix); one missed by more holds you there, but only when the arriving train reported it: one missed by the plan's own estimate alone counts as made once the onward train has left (0.63.3, reported: held at Vallorcine by a +7 known at planning, and a train held at is never asked about again), and held, the card says Train missed with Change trip. A journey OJP does not know (`TRIPINFO_NOJOURNEYFOUND`) is `UnknownJourneyError`, the MCP's `train_status` answers `unknown_journey`, not an outage.
  - Asked on the day, an answer carries `<EstimatedTime>` beside `<TimetabledTime>` (one recorded, Bern → Interlaken Ost on 4 Nov 2026, `tests/fixtures/ojp/estimates/live.xml.gz`, with a train that does not serve Bern; `tests/estimates.test.ts`, which also makes its own). `tests/liveFacts.test.ts` (report only, skipped without `OJP_LIVE_URL`; run by `live.yml`) says whether same-day answers still carry them and `<Cancelled>` / `<NotServicedStop>` (seen 4 Nov 2026), and `LIVE_FACTS_SAVE=<file>` keeps one. `StopCall.dep/arr` and `Connection.dep/arr` are always the timetable's (links, calendar, the question asked again by `refresh.ts`); a delay known is `depEst/arrEst` beside them (0.15.0). The planner chains legs on the expected times (`expectedDep/expectedArr` in `connection.ts`) and says a change tight across two legs as `warningsFor` says one within a connection; the live view shows the plan's delay until the train reports, then what it reports, on time included; notifications come for the expected times. Platforms as times (0.17.2): `platform` is the timetable's (`PlannedQuay`), what links, calendar and print carry; one the service already knew another (`EstimatedQuay`) is `platformEst` beside it, the only one where no plan came. The ride shows the train's report, else `platformEst`, else the plan's, and a change against the plan as both (`platformAt`, `platformMoved` in `src/core/live.ts`); one taken back shows nothing. Each ride's `destination` is the service's `DestinationText`.
  - A line closed that day (Mürren–Grütschalp–Lauterbrunnen, 2–3 Nov 2026) answers nothing at all, with or without a via. The planner's ladder for a leg: all vias and lines' modes; else the vias that have a connection from the one before (`reachableRules`), one request each; only then none.
  - A situation names the train (`AffectedVehicleJourney`), not the stops. Whether a notice concerns the stretch you ride is read from its words, "zwischen A und B" in four languages (`onThisStretch` in `src/core/warnings.ts`); one about another stretch of the train's route is `disruption-away`: said in blue, not counted against the plan. A stretch counts only when you ride it (0.18.1, reported on the MCP: VAE St. Gallen–Luzern flagged for Luzern–Ebikon, IC1 Lausanne–Zürich for Lausanne–Genève-Aéroport): both ends among the ride's calls, or one of them and the other within 2 km of its track and not beyond either end (an express passing it; `place` is `placeByName` in `src/core/stops.ts`, injected into the planner and refresh). A replacement bus (`EV`) whose ends lie by two stations of a line the leg rides says that line's stretch is by road (`replacement-bus`, `lineReplaced`): the Albula closure in T1 is said that way, not as the trains' notice. Such a bus passes the line's stations between its ends by road (`Section.byRoad`, set by the planner's `markByRoad`; `visited` and `plannedRows` count them): the Albula's express bus Thusis–Preda (6 Nov 2026, `B1R`) rides the line, where it counted as missing Filisur and Bergün and the line asked for was planned via the Vereina (reported on the MCP, 5 Nov 2026). Stops are looked up by `stopKey`, as a bus stand's ref carries its quay. A leg whose line still cannot be ridden says so as an error naming it and its stations (`line-missed`, `lineMissed`, scored well behind one that rides it); the MCP never recommends such an option while another rides the line, and with `strict` answers `line_not_ridden`, no options and why. A ride touching one end of a stretch only at its first or last call (0.21.5) is on it when it lies inside (its far end nearer each named place than they are to each other: the Mont-Blanc Express Les Marécottes–Vallorcine for "Martigny–Vallorcine"), else away (from the other side: Olten–Luzern for "Luzern–Ebikon"), and away when where things are is not known. A notice names a stretch also as "from X" ("ab Erstfeld", dès, da, from) or "up to X" (bis, jusqu'à, fino a): from X onwards in the direction of travel (a ride ending at or before X is elsewhere), and the warning names that stretch (`wDisruptionFrom`, `noticeStretch`, `stretchHere`). A situation weighs by its words (`gradeNotice` in `src/core/noticeGrade.ts`, `NoticeInfo.grade`, 0.21.2, retest of 5 Nov 2026: a 1-min shift "ab Erstfeld" was an error): OJP's own `Severity`/`Priority`/`Planned` say normal/3/true on every recorded situation (63), so headline and consequences decide, in four languages: closed or cancelled an error, restricted, replaced, rerouted, late or a stop left out a warning, anything else ("Information zu …", reservation advice) info; a closure ridden by its own replacement bus only a warning; scored by grade (error 1, warn 0.5, info 0.1 of `disruption`), and the facts line counts warn and error only. A ride's track without its geometry (the MCP drops tracks) is drawn through its stops by `stopKey`, as a ref carries its quay: the track was empty and every notice "on" (Thusis–Preda said on the IR38 from Preda). A situation's validity, the stops it names and the operator's description and remarks are kept beside its headline (`Section.noticeInfo`: `until`, `affected`, `detail`), shown when the notice is opened and in the MCP (`validUntil`, `affected`, `detail`). Arriving on a later day has no rule of its own (0.64.1; `sameDayFirst` dropped every option arriving the next day while one arrived the same day, so Zürich → Stockholm offered no night train from Hamburg, nor anything after 01:08): the score counts its hours, so a way back the next morning is not recommended over one that evening, and the options strip says the arrival's day (`+1`). Old `next-day` warnings still read. A scenic line's own stretch ridden after sunset + `DUSK_MIN` (15 min) at its middle station is said from when it is dark (`line-after-dark`, `linesAfterDark` in `src/core/warnings.ts`, weight 20: of otherwise equal options the one by day; 0.20.0, reported on the MCP: a 16:05 Gotthard option on the mountain line by night). A stay's window (`Waypoint.leaveBy`, `arriveAfter`, `HH:MM` on the trip's date): a leg leaves a stop by its `leaveBy`; once any option leaves in time, those that cannot are not offered (`inTime`, 0.21.5); only when none can, the connections there are each said as late (`window-missed`, error, weight 120, `leavingBy` in `src/core/planner/plan.ts`), and a stay starts at its `arriveAfter` at the earliest; links carry them (`#/r/` modifiers `f<hhmm>`/`u<hhmm>`, `#/s/` slots 9 and 10; the old never-enforced slots 7 and 8 and modifiers `a`/`b` stay read past), riding through drops them (`setEntryStay`), the panel no longer sets it (0.51.0: links and the MCP still do, `setEntryLeaveBy` for tests), a length or time set there drops it, and the line says it ("Stay 30 min, by 17:30"). Waiting after the time asked for costs as travel does (0.21.6, round 3, 6 Nov 2026: Nyon–La Cure from 09:00 recommended the 13:29 for a ride a minute shorter than the 09:29; Zürich–Gotthard–Lugano from 08:00 the 10:05): a chain scores its time from the asked time, arrive-by its time to the asked arrival (`planFrom`, `plan`). A notice its words grade as information is a `notice` ("Notice A–B"), a reservation advice `reservation-advised`, neither a disruption, both blue (`NOTICE_TYPES` open the operator's text). A replacement bus is category `EV` or a bus whose line is named so (`EV2`, category `B`: the Mont-Blanc Express, `isReplacementBus`); its ends are placed along the line's course through its stations (`lineStretch`), not only at them. `stopKey` reduces a UIC number with OJP's generated platform part (`8301003_gen:missingSLOID_pf:31`, Domodossola said not reached). GA and day-pass notes (`not-ga`, `ga-unknown`) are for those tickets only; the app's ticket is the GA. A tight change at a line's `timedChanges` station (Grütschalp: the train waits for the cable car) is `timed-change`, info, not scored; the live view's risk is unchanged. A leg whose next connection in the same answers leaves over `GAP_MIN` (120 min) after the planned one says when (`sparse`, info, not scored, `gapWarning` in `src/core/planner/plan.ts`); nothing when the answers hold none later. Stops abroad DIDOK does not list (Chamonix-Mont-Blanc, Vallorcine, Domodossola) are in the stop index by their UIC number (`EXTRA` in `scripts/build-stops.ts`, `UIC_MIN` in `src/core/stops.ts`) and keep it as ref and key, as OJP refuses `ch:1:sloid:<uic>` (`stopKey`); the GA and day passes end at Le Châtelard-Frontière (`ABROAD` in `scripts/build-ga.ts`), and a GA note names the stretch uncovered, not the whole ride (`gaStretchOf`).
- Acceptance tests (`tests/acceptance.test.ts`) replay the planner's own OJP requests from `tests/fixtures/ojp/<tour>/<sha1>.xml.gz` (tracks thinned to every 20th point). A planner change that alters its requests needs new answers: `NODE_USE_ENV_PROXY=1 OJP_RECORD_URL=<Worker URL> npm run record:ojp:missing` records only the missing ones through the app's Worker (no key); a full re-record is `npm run record:ojp` with `OJP_API_KEY`. `tests/fixtureIndex.test.ts` keeps each tour's `index.json` and files in step; `FIXTURE_LOG=<file> npm run e2e` lists the fixtures the e2e tests read (T5's second answer is read only there).
- e2e (`e2e/fixtures.ts`): every test fails on an uncaught page error or `console.error`; the Worker URL is answered by the Worker's own `handle()` (its checks and sync mailbox, in memory) with the recorded acceptance answers in place of OJP; a query the Worker would refuse, or a trip query with no recorded answer, fails the test (a test about the service failing says so first: `allowUnrecorded(page)`). `newTrip(page, ...stations)` and `pick(page, text)` are the one add flow. `e2e/acceptance.spec.ts` plans T1–T6 through the UI (every option, export, map), so planner changes that break a screen fail before release.
- Render code never reads `Date.now()` (React purity): use `useNow()` (`src/ui/useNow.ts`), a shared 15 s clock. Tests drive it with `page.clock`.
- `src/ui/` may import from `core/`, never the other way round.
- Keep each file under 800 lines; split before adding to it.
- Tests build tours with the 0.3 builder's edits and write old links (`tests/helpers/edit.ts`, `routeLink.ts`, `share.ts`); the app only reads old links and edits entries (`src/core/line.ts`).

- Curated data: `src/data/templates.json` (types in `src/core/data.ts`; a line is enforced by its must-pass stations and its modes, nothing else: the avoided-segment rule was redundant and went in 0.6.3). `ga.json` is generated (`npm run data:ga`) from SBB's OSDM fares; it covers fares SBB sells, so other operators' summit lines (Niesen, Harder…) are missing, never guessed. Unknown is never covered (0.21.5, retest round 3: Interlaken Ost → Jungfraujoch said nothing): a cable car or cog railway with neither a rule nor evidence of cover says `ga-unknown` (info, not scored; `gaUnknown` in `src/core/warnings.ts`); the evidence is `ga.covered`, the summit stretches with a GA fare of 0 in the same OSDM data (Rigi, Grütschalp…), each end with the stops within 1 km. A fare names a place's main station; where its two ends share no mode, the generator moves an end to the nearest stop within 1 km that has the other's (Mürren BLM → Mürren (Schilthornbahn), Zermatt → Zermatt GGB), as rides are matched by the stops they call at (`tests/ga.test.ts`). Highlight names are in the four languages (`name` per language, a plain string still read, `highlightName`); warnings and notices carry the highlight's id (`highlight`) and its English name, and the screen, notifications and MCP put it in theirs (`localParams`). Which way a line runs where it is put (`lineReversed` in `src/core/lineDirection.ts`, the add sheet and the MCP): towards the station after it when that is one of its ends (Zürich, Voralpen-Express, Luzern runs from St. Gallen), else from the station before when that is one, else from the end nearer it. Seat sides (`seat`, from `seatFrom` when only part of a line has the view) are in chain order, with their sources in `src/data/SEATS.md`; `src/core/seat.ts` flips them for a ride the other way (the ride's row, and a highlight's notification). Must-pass stops must be stops trains call at (OJP lists only those): Wassen, for one, is not. Each line added since 0.19.0 has an acceptance test planning it end to end on recorded answers that calls at every must-pass stop (`L*` in `tests/acceptance.test.ts`: LMBE, LNSTCM, LCENTO, LMOB, LVIGNES); a new line gets one, recorded with `record:ojp:missing`.

## The app as it is (0.64.0)

Four jobs, one place each: **where** (the stations), **when** (the connection), **ride** (under way), **keep or share**. A trip is a date, a time it leaves from and its stations; everything else is derived. History, and how each piece came to be: [`docs/HISTORY.md`](docs/HISTORY.md) (superseded wherever it disagrees with this section).

- **The list** (`src/ui/Home.tsx`, `sortTrips` in `src/core/trip.ts`): under way, ahead, past trips folded. The card of a trip under way says its next step, the time first (`nextStep`). New trip opens the trip with the search open; an empty trip made here is tidied away.
- **One trip per day of travel** (0.64.0, `src/core/nights.ts`): a trip ends where you sleep. A stay ends the day it starts (the panel has no day to pick; a stay given as a length may run past midnight, a wait for a late train, and is no night); a night train is a ride in a trip, never split. A trip kept until a later day than it arrives at a station (older trips, links, other devices' older versions) is split there once (`splitNights`, on load, `add` and sync's `replaceAll`): `<id>`, `<id>-2`… so devices splitting alike make no copies, each next part on the stay's day from its time, all planned again. The MCP refuses a `stayUntil` after the trip's day (`overnight_stay`).
- **The trip** (`src/ui/TripScreen.tsx`, one screen, `#/trip/<id>`; `/edit`, `/replan` open it too): date and time (`WhenField.tsx`, rules in `src/core/when.ts`: back up to `PAST_DAYS`, 14), name, the options strip (`OptionsBar.tsx`: the day's connections, its arrows load earlier and later), notices (`PlanNotices.tsx`), the line. Every edit plans again after 400 ms of quiet (`usePlanner.ts`, `src/io/planTrip.ts`; `autoplan.ts` plans trips without a timetable in the background). Its time decides only whether it is under way (`isLive`); otherwise it is edited in place, past ones too.
- **The line** (`src/ui/TripLine.tsx`, rows from `src/core/rows.ts`): your stations dark, the plan's muted; each ride with its badge, kind (`product.ts`), where it goes, its stops (folded), duration, seat side, how full, platforms at the stations (`stationPlatforms`); a change is two dots; walks dotted; new days marked (`src/core/days.ts`); heights from 1000 m; a station no connection passes struck through, with why and Try an hour later (`MissedNote.tsx`); warnings under what they concern (`src/core/warnings.ts`). Wording in `stayLabel.ts`.
- **Where**: a station is yours or the plan's. Yours open a panel (`StationPanel.tsx`): no stop or a stay (`StayRow.tsx`: a length or until a time on the day it starts, `src/core/stay.ts`), the line leading there (×), Add after, up, down, remove; the open one drags by its grip. The plan's (a change, a stop inside a ride) say why and offer one action, Keep this station (`pinAfter`), which makes it yours. Adding is one search (`AddSheet.tsx`): recent stations, stations (`StopSearch`, umlauts folded, one typo forgiven), places people go to (`src/data/attractions.json`), scenic lines (`src/data/templates.json`, run the way the trip goes, `lineReversed`), your past trips, stations abroad on a tap (Transitous), and Back to <start>; a new trip's search first offers From <the end of the trip ahead that leaves last>, on the day after it (`onwardFrom`). Entries and lines: `src/core/line.ts` (`entriesOf`, `fromEntries`, rings, `linesOf`).
- **Ride** (from `LIVE_BEFORE_MIN` before the first train to `LIVE_AFTER_MIN` after the expected arrival): the trip is followed (0.63.0): the name, progress, next step, risks and the line read only; date, time, options, rename and the departure → arrival headline behind the bar's pencil, Change trip, its check, Done, back (0.63.1; `changing` in `TripScreen.tsx`; any edit made there sets it, so a trip put in that goes live stays open; opened anew it is followed; no prompt, no setting). Followed, what is live over it: progress, the next step, connections at risk (`TripLive.tsx`); changing (0.63.2), the same screen as at any time (0.62.0) without that tile, only Undo last change (`UndoChange`) and the line's live times and marker, as a delay matters when choosing; both (`src/core/live.ts`, `useLive.ts` asks the Worker's `/journey` for the train you are on and the next one when it is close). The plan is edited as ever: a time or another connection replaces it; a change of the stations is made on what lies ahead from where you are (`change` in `TripScreen.tsx`: the rest from `restDraft`, an entry's place mapped onto it; the entries behind you `fixed`, the last of them only Add after), planned and the trip's once planned (`RestApply.tsx`, `mergeReplan`, `revise`), the line waiting meanwhile. Notifications on Android (`src/core/notify.ts`).
- **Keep or share**: Share (`ShareSheet.tsx`): Send link (`#/s/`, `src/core/export/tripLink.ts`, a few hundred characters), Calendar (`.ics`), Print (`src/styles/print.css`, imported last), each leg on sbb.ch (`legLinks`). More: Reload trip (`src/core/refresh.ts`, also pull to reload), Notifications on or off (`Trip.quiet`), Duplicate, Delete (Undo on the list). Links opened: `#/s/` and `#/j/` show the trip read-only with Save (`SharedTrip.tsx`); route links `#/r/`, `#/t/`, `#/tour/` a route to plan as a new trip (`SharedTour.tsx`, `src/core/export/routeLink.ts`: a line by its rings `@` and its end `l<template>`).
- **The map** (`src/ui/MapView.tsx`, `#/trip/<id>/map`): the trip's route and stations, names kept apart and off the line (`placeLabels` in `src/core/mapLabels.ts`, `mapNames.ts`), the plan's changes as smaller rings, a dark style on a dark device, the plain ground without the tile host, where you are (`src/core/position.ts`; the device's location only on its button, in memory only, never moving the map). The map as seen is kept for offline (the service worker's `MAP_CACHING` in `vite.config.ts`; without one, `src/io/mapCache.ts` through `srrmap://`; tiles keyed without the planet build, `tileKey`). Nothing is fetched ahead.
- **Weather** on the line only: a stripe at its right (`WeatherCell.tsx`, `useWeather.ts`, `src/core/weather.ts`; one Worker `/weather` call a trip, Open-Meteo, MET Norway when refused), rain bars, a tap for the values, dimmed under way to where you are; a week out, "Weather from <date>".
- **Desktop** (`useColumns.ts`, `Columns` in `src/App.tsx`): from 860 px the list beside what it opens (a trip or its map), each column a transformed box framing what a phone shows fixed.
- **Sync** (SPEC §3b): `src/core/sync.ts` (key, HKDF, AES-GCM, stamps, merge), `src/io/sync.ts` (the engine; a round rebases its merge onto edits made meanwhile, `rebase`), `Settings.tsx`, `QrScanner.tsx`; the Worker keeps ciphertext only (`workers/ojp/src/sync.ts`, Durable Object `SyncBox`). Items this version cannot read are held as they came, never deleted (`held` in `src/io/listStore.ts`).
- **Storage**: `src/trips.ts` on `src/io/listStore.ts` (item by item in one IndexedDB transaction; what a closing page could not finish waits in localStorage, `settleUnsaved`); legacy routes (`srr.tours.v1`, `src/tours.ts`) come back once as past trips (`migratePastTrips`). Every timetable answer is kept on the device (`src/io/answers.ts`: until its day starts, on the day 15 min, one with no connection 15 min). Reservation-only trains are avoided where another goes (the planner's `avoid`, no setting).
- **Settings**: language, sync, the debug log (opt in, `src/io/log.ts`, never a key or anything decrypted), where the data comes from (`SOURCES`, as the open data licences ask), version and build.

## Android

- Capacitor shell in `android/` (app ID `ch.brunodev.swissrailroutes` and the release key are permanent). `npm run android:sync` builds and copies `dist/` in (gitignored). `src/native.ts` owns `isNative`; the service worker and update banner are web-only (the banner asks the worker for a new version on every return to view and hourly, `src/ui/updateCheck.ts`: a hash-routed tab never navigates).
- Back button: `src/io/back.ts` (`@capacitor/app`) goes up one screen (`parentOf`, `src/core/parent.ts`), replacing the address; on the main list the app goes to the background.
- Notifications: `src/core/notify.ts` (pure: 10 min before a departure, 5 before an exit, 10 before a highlight; none where the same train runs through a stop; none for a trip turned quiet, ⋯ → Notifications off, `Trip.quiet`, synced, 0.44.0) and `src/io/notifications.ts` (cancels all first, then reschedules, on every trips change; without the stop index the trains still, the highlights not; no-op on the web). Texts in i18n (`n*`).

## MCP

- `mcp/` (see its README): the app's core in a Node server on the VPS, no fork: `src/worker.ts` is the adapter (`src/io/` is browser-only), `src/route.ts` a request as a route, `src/tools.ts` the six tools (`reachable_from` (0.28.0): the map planner's web from a stop at a time, every place reached without a change within 3 h with its arrival and train, and `estimateFor` places by the nearest reached and a change, one Worker `/departures` call; `find_stops` takes `abroad` (0.35.0: stations abroad as `abroad`, one Worker `/eu/stops` call; `plan_trip` takes one by its `eu:` ref with its name, refused without) and `near` (a point, `km` the width looked at, `buses`) as the map's tap does (`nearbyChoices`); each ride's `from`/`to` carries `source`: `yours`, `line` or `plan`; `list_scenic_lines` says `reservationOnlyTrains` and why the line itself needs none; `reservation` is deprecated; `stops[].stayUntil` (0.47.0, `YYYY-MM-DDTHH:MM` on the trip's day, 30 min when no `stay`, refused before it and, 0.64.0, after it with `overnight_stay`, the link's `n` modifier); `stops[].leaveBy`/`arriveAfter`; `returnWay: "fastest"` with `roundTrip` goes straight home after the last stay, in `src/route.ts`), `train_status` answers `not_available` for a train run outside Switzerland (a `…:ojp:…` journey from a plan) and says an undated id needs its date; ## Invariants

- Storage keys follow `srr.<name>.v<N>` (IndexedDB: `srr.tours.v1`, `srr.trips.v1`, `srr.plans.v1`, `srr.options.v1`, `srr.sync.v1`, `srr.syncLast.v1`, `srr.log.v1`, and the database `srr.answers.v1`; localStorage: `srr.prefs.v1`, `srr.recentStops.v1`, `srr.logging.v1`, `srr.unsaved.trips.v1`, `srr.unsaved.tours.v1`; retired: `srr.oneList.v1`; sessionStorage: `srr.opened.v1`, set when the app opened in this tab, so a reload never jumps to the trip under way; Cache Storage, web only: `srr-mapstyle-v1`, `srr-tiles-v1`, the map as seen). Never rename an existing key: bump the version and migrate.
- Leg queries (stops, date, time) go to the Worker; nothing else leaves the device (the device's location never does), except with sync on: trips, your past trips and the stations you entered lately, encrypted on the device with a key only the devices hold (`src/core/sync.ts`; the Worker stores ciphertext under an id derived from the key). Never send the key, or anything decrypted, anywhere. CSP `connect-src` lists only the Worker and the tile host.
- API keys exist only as Worker secrets.
- Curated data in `src/data/` is schema-checked by a test; a template change needs a fixture run of T1–T6.
- Tests never hit the network: OJP answers are recorded fixtures. Live checks run only in `live.yml`.
- No user-facing string is hard-coded. Add it to `src/i18n/en.ts` and to de, fr, it.
